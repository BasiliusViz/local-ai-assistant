# Как подключить ИИ-ассистента в VS Code

Ассистент работает внутри нашей сети: пишет код, ищет в документации,
в коде, в задачах Jira и в уязвимостях DefectDojo. Ничего наружу не уходит.

Выберите свою систему:

- [Windows](#windows)
- [Linux](#linux)

Перед началом узнайте у администратора (или в канале команды):

| Что | Значение |
|---|---|
| Адрес сервера с моделью | `<ВСТАВИТЬ>` (дальше в командах — `АДРЕС-OLLAMA`) |
| Адрес сервера поиска | `<ВСТАВИТЬ>` (дальше — `АДРЕС-СЕРВЕРА`) |
| Где лежат установщики | `<ВСТАВИТЬ ПУТЬ К ПАПКЕ С VS CODE И CONTINUE>` |
| Где токен в Vault | `<ВСТАВИТЬ АДРЕС VAULT>`, путь `<ВСТАВИТЬ ПУТЬ>` |

# Windows

## Шаг 1. Установить VS Code

Если VS Code уже стоит — переходите к шагу 2.

**Мышкой:** запустить `VSCodeUserSetup-x64-*.exe` из папки с установщиками,
на экране «Дополнительные задачи» оставить галочку **«Добавить в PATH»**,
дальше «Далее» до конца.

**Или командой** (PowerShell, из папки с установщиком):

```powershell
.\VSCodeUserSetup-x64.exe /VERYSILENT /NORESTART /MERGETASKS=!runcode,addtopath
```

(`VSCodeUserSetup-x64.exe` замените на точное имя файла.)

После установки **закройте и заново откройте** окно PowerShell и проверьте:

```powershell
code --version
```

Показал номер версии — всё в порядке.

## Шаг 2. Скачать файлы настройки

Нужны три файла в одной папке:

- `setup-continue.ps1` — скрипт настройки;
- `continue-config.example.yaml` — образец настроек;
- `continue-*.vsix` — само расширение Continue (из папки с установщиками).

Проще всего склонировать репозиторий проекта и положить `.vsix` рядом:

```powershell
cd $HOME
git clone <ВСТАВИТЬ АДРЕС РЕПОЗИТОРИЯ> local-ai
cd local-ai
```

## Шаг 3. Взять токен в Vault

1. Открыть Vault в браузере: `<ВСТАВИТЬ АДРЕС VAULT>`, войти.
2. Перейти в `<ВСТАВИТЬ ПУТЬ>`.
3. Скопировать значение токена (кнопка копирования рядом с полем).

Токен никому не пересылать и никуда не вставлять, кроме шага 4.

## Шаг 4. Запустить скрипт настройки

**Закройте VS Code**, если он открыт. В PowerShell, в папке с файлами:

```powershell
powershell -ExecutionPolicy Bypass -File .\setup-continue.ps1 -OllamaUrl http://АДРЕС-OLLAMA:11434 -ServerUrl http://АДРЕС-СЕРВЕРА -Vsix .\continue.vsix -Model qwen3.6:35b -ContextLength 32768
```

(`continue.vsix` замените на точное имя файла.)

Скрипт спросит токен: вставьте его правой кнопкой мыши или `Ctrl+V` —
символы **не будут видны**, это нормально — и нажмите Enter.

Скрипт сам:
- поставит расширение Continue;
- отключит отправку статистики наружу;
- запишет настройки с вашими адресами и токеном;
- проверит, что модель и все серверы поиска отвечают.

В конце должно быть **«Готово»** и везде `[OK]`. Если где-то `[FAIL]` —
смотрите [«Если что-то пошло не так»](#если-что-то-пошло-не-так).

## Шаг 5. Настроить VS Code

1. Открыть VS Code.
2. Слева нажать значок **Continue**.
3. Вверху панели выбрать **Local Assistant**. Если предлагает войти в
   аккаунт — закрыть, не нужно.
4. Внизу окна чата переключить режим с **Chat** на **Agent**.
   Без этого поиск работать не будет.
5. В строке ввода нажать значок **инструментов**. Для `knowledge-base`,
   `code-graph` и `defectdojo` нажимать на надпись справа, пока не станет
   **Automatic**. Тогда ассистент не будет спрашивать разрешение на каждый
   поиск (наши инструменты только читают, ничего не меняют).

## Шаг 6. Проверить

Задать в чате по очереди:

1. `напиши функцию на Go, которая разворачивает строку` — должен ответить
   кодом.
2. `поищи в базе, как у нас согласуется выкладка в прод` — должен сходить в
   поиск (в чате появится блок `kb_search`) и ответить со ссылкой на
   документ.
3. `посмотри в коде, где проверяется токен авторизации` — должен сходить в
   `code_search` и показать файл и строку.

Все три сработали — **готово**. Дальше — [как задавать
вопросы](#как-задавать-вопросы).

# Linux

## Шаг 1. Установить VS Code

Если VS Code уже стоит — переходите к шагу 2.

Установщик взять из папки с установщиками: `.deb` для Ubuntu/Debian/Astra,
`.rpm` для RHEL/РЕД ОС/Fedora.

Ubuntu / Debian / Astra:

```bash
sudo apt install ./code_*_amd64.deb
```

RHEL / РЕД ОС / Fedora:

```bash
sudo dnf install ./code-*.x86_64.rpm
```

Проверить:

```bash
code --version
```

Показал номер версии — всё в порядке.

## Шаг 2. Скачать файлы настройки

- `setup-continue.sh` — скрипт настройки;
- `continue-config.example.yaml` — образец настроек;
- `continue-*.vsix` — само расширение Continue (из папки с установщиками).

Проще всего склонировать репозиторий проекта и положить `.vsix` рядом:

```bash

git clone <ВСТАВИТЬ АДРЕС РЕПОЗИТОРИЯ> local-ai
cd local-ai
```

Для скрипта нужны `curl` и `python3` — обычно уже есть. Проверить:

```bash
curl --version && python3 --version
```

1. Открыть Vault в браузере: `<ВСТАВИТЬ АДРЕС VAULT>`, войти.
2. Перейти в `<ВСТАВИТЬ ПУТЬ>`.
3. Скопировать значение токена.

Если привыкли к консоли и `vault` CLI настроен — скрипт может взять токен
сам, см. шаг 4.

Токен никому не пересылать и никуда не вставлять, кроме шага 4.

**Закройте VS Code**, если он открыт. В терминале, в папке с файлами:


(`continue.vsix` замените на точное имя файла.)

Скрипт спросит токен: вставьте его (`Ctrl+Shift+V`) — символы **не будут
видны**, это нормально — и нажмите Enter.

Взять токен через `vault` CLI вместо ручного ввода: сначала `vault login`,
потом добавить в конец команды `--vault-path <ВСТАВИТЬ ПУТЬ>`.

Скрипт сам:
- поставит расширение Continue;
- отключит отправку статистики наружу;
- запишет настройки с вашими адресами и токеном;
- проверит, что модель и все серверы поиска отвечают.

В конце должно быть **«Готово»** и везде `[OK]`. Если где-то `[FAIL]` —
смотрите [«Если что-то пошло не так»](#если-что-то-пошло-не-так).

## Шаг 5. Настроить VS Code

1. Открыть VS Code.
2. Слева нажать значок **Continue**.
3. Вверху панели выбрать **Local Assistant**. Если предлагает войти в

# Как задавать вопросы

Ассистент сам решает, искать или отвечать из своих знаний. Чтобы искал —
скажите, где.

| Что нужно | Как спросить |
|---|---|
| Регламент, процесс | «**поищи в базе**, какие требования к паролям» |
| Страница в Confluence | «что **в конфлюэнсе** про дежурства» |
| Место в коде | «**посмотри в коде**, где обрабатываются куки» |
| Параметры сборки | «**в коде**: какие параметры у джобы AA/asan» |
| Кто вызывает функцию | «кто вызывает шаг `abActions`» |
| Задачи | «**jira**: что открыто на Иванове в DEVSEC» |
| Уязвимости продукта | «**dojo**: критичные в abinf» |
| Общая картина по всем продуктам | «**dojo** общая картина», «**dojo** какие продукты есть» |
| Худшее по всем продуктам | «**dojo** где у нас критичные» |
| Тема по всем продуктам | «**dojo** где у нас log4j» |
| Отчёт по продукту | «**dojo** подготовь документ по критичным в abinf» |

- Задачи ищутся **только со словом «jira»**, уязвимости — **только со
  словом «dojo»**.
- Задачи и уязвимости обновляются раз в 2 часа, код — раз в сутки. Точный
  статус «прямо сейчас» смотрите в самой Jira.
- Ответ без ссылки на источник — это общие знания модели, а не наша база.

# Если что-то пошло не так

## Скрипт написал [FAIL]

| Что написано | Что делать |
|---|---|
| `VS Code не найден` | закрыть и заново открыть терминал; не помогло — переустановить VS Code (шаг 1) |
| `не установилось. Marketplace закрыт?` | добавить в команду путь к файлу `.vsix` |
| `доступ запрещён (401/403)` | токен неверный — скопировать из Vault заново, целиком |
| `в токене пробелы или не-латиница` | скопировалось лишнее — скопировать заново |
| `нет связи с ...` | проверить адрес в команде; верный — написать администратору |
| `8010: не отвечает` / `8011: не отвечает` | написать администратору, какой порт не отвечает |
| `8012: не отвечает` (жёлтым) | это DefectDojo, он открыт не всем. Не нужен — добавить `-NoDojo` (Windows) или `--no-dojo` (Linux) |
| `running scripts is disabled` (Windows) | запускать именно как в шаге 4: `powershell -ExecutionPolicy Bypass -File ...` |

Скрипт можно запускать сколько угодно раз — ничего не сломается, старые
настройки сохраняются в копию.

## В VS Code

| Что происходит | Что делать |
|---|---|
| Ассистент не ищет, отвечает «из головы» | режим **Agent**, а не Chat; и назвать, где искать («поищи в базе», «посмотри в коде») |
| Нет инструментов в списке | закрыть **все** окна VS Code и открыть снова |
| Каждый раз спрашивает разрешение | шаг 5, пункт 5 — поставить **Automatic** |
| Ответ обрывается на середине | написать администратору |
| `Request timed out` | модель просыпается после простоя — повторить через полминуты |
| Надпись `-32601 Method not found` | не ошибка, не обращать внимания |

# Для администратора: что делает скрипт и как без него

Скрипт ставит расширение (`code --install-extension`), выключает
`continue.telemetryEnabled` в настройках VS Code и пишет
`~/.continue/config.yaml` (Windows: `C:\Users\<логин>\.continue\config.yaml`)
из `continue-config.example.yaml`, подставляя адреса, токен, модель и
контекст. Режим Agent и политику Automatic Continue хранит у себя, их
командой не выставить — поэтому шаг 5 ручной.

Все параметры:

| Windows | Linux | Зачем |
|---|---|---|
| `-OllamaUrl` | `--ollama` | сервер с моделью, обязательно |
| `-ServerUrl` | `--server` | сервер поиска без порта, обязательно |
| `-Vsix` | `--vsix` | файл расширения; без него — из Marketplace |
| `-Model` | `--model` | модель чата |
| `-ContextLength` | `--context` | контекст; не больше реального окна на сервере, иначе ответы обрываются |
| `-VaultPath`, `-VaultField` | `--vault-path`, `--vault-field` | взять токен через `vault` CLI |
| `-NoDojo` | `--no-dojo` | без DefectDojo |
| `-SkipExtension` | `--skip-extension` | не ставить расширение |
| `-NoToken` | `--no-token` | модель без шлюза, без заголовка `x-api-key` |

Если скрипт запустить нельзя — положить в `config.yaml` этот текст, заменив
`АДРЕС-OLLAMA` (2 раза), `АДРЕС-СЕРВЕРА` (3 раза) и `ТОКЕН` (2 раза), и
выключить телеметрию: `Ctrl+,` → `continue telemetry` → снять галочку.

```yaml
name: Local Assistant
version: 1.0.0
schema: v1

models:
  - name: qwen3.6:35b
    provider: ollama
    model: qwen3.6:35b
    apiBase: http://АДРЕС-OLLAMA:11434
    roles: [chat, edit]
    capabilities:
      - tool_use
    keepAlive: -1
    defaultCompletionOptions:
      contextLength: 32768
      maxTokens: 2048
      temperature: 0.3
    requestOptions:
      headers:
        x-api-key: ТОКЕН

  - name: BGE-M3 Embed
    provider: ollama
    model: bge-m3:567m
    apiBase: http://АДРЕС-OLLAMA:11434
    roles: [embed]
    requestOptions:
      headers:
        x-api-key: ТОКЕН

mcpServers:
  - name: knowledge-base
    type: streamable-http
    url: http://АДРЕС-СЕРВЕРА:8010/mcp

  - name: code-graph
    type: streamable-http
    url: http://АДРЕС-СЕРВЕРА:8011/mcp

  - name: defectdojo
    type: streamable-http
    url: http://АДРЕС-СЕРВЕРА:8012/mcp

rules:
- Отвечай по-русски.
- Выбор инструмента. Про исходный код («где в коде», «в каком файле», «куда править») — code_search.
  Про регламенты, процессы и требования — kb_search. Про связи в коде (кто вызывает, что сломается)
  — инструменты code-graph. Про задачи — jira_search, и только если в сообщении есть слово «jira».
  Про уязвимости продуктов — dojo_findings, и только при слове «dojo» или «defectdojo».
- 'Названный источник — это уже просьба искать, глагол не нужен: «что у нас в конфлюэнсе про дежурство»
  — зови kb_search с source_filter="confluence".'
- 'Фильтры — отдельные аргументы, а не часть query. У jira_search это person, project, status, issue_key;
  у dojo_findings — product, status, severity. Фамилия или номер задачи, положенные в query, не найдут
  ничего: эти поля в тексте не хранятся. В query кладут только тему, и только если она есть в вопросе.'
- Если ты вызвал инструмент — отвечай по тому, что он вернул, и не придумывай имена файлов, пути,
  команды и ссылки, которых в ответе не было. Лишние фрагменты в выдаче — это нормально, молча игнорируй
  их. Если инструмент не вызывался, отвечай обычным образом, своими знаниями.
- 'Всегда показывай, откуда ответ: документ со ссылкой, файл со строкой, номер задачи, ссылку на находку.
  Если инструмент вернул поле citation — скопируй его дословно, вместе с путём.'
- Задачи и находки берутся из индекса, а не из живой системы. Если речь о статусе или количестве,
  добавь, на какую дату данные, и предложи свериться в источнике.
- 'Пустой ответ инструмента — так и скажи, не выдумывай. Но сперва подумай, тот ли инструмент ты позвал:
  поиск по документации не видит ни код, ни задачи, ни уязвимости.'
- У инструментов code-graph не заполняй параметр project_path — сервер уже настроен на нужный граф,
  а путь наугад даст ошибку «graph.json not found».
- 'Шаги Jenkins в графе называются по имени файла из vars/ (abActions), пайплайны — «репозиторий/путь»
  (billing/Jenkinsfile). Кто использует шаг или что он вызывает — get_neighbors с label = имя шага:
  стрелка <-- это вызывающие, --> вызываемые. query_graph для этого не подходит — он идёт только вперёд.'
- 'Просят документ, отчёт или сводку по уязвимостям продукта — зови dojo_findings
  с response_format="report" и пиши по возвращённым полям description, impact и
  mitigation, а не по своим знаниям: там написано, что нашёл конкретный сканер в
  конкретном месте. Ответ длинный, поэтому разумно сузить отбор по уровню.'
- 'Оформление: шаги — нумерованным списком, команды и пути — в блоках кода. Без эмодзи.'
```
