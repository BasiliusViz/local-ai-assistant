# Ассистент в VS Code: подключение

Модель и поиск работают внутри контура, ни код, ни вопросы наружу не уходят.
Ассистент пишет код и по просьбе ищет в документации (Confluence), в коде
наших репозиториев, в задачах Jira и в находках DefectDojo.

Порядок: подготовить (раздел 1) → запустить скрипт (2) → три действия
мышкой в VS Code (3) → проверить в чате (4). Около 10 минут.

---

## 1. Что подготовить

| Что | Где взять |
|---|---|
| **VS Code** | внутренний ресурс ПО. Команда `code` должна работать в терминале: на Windows установщик добавляет её в PATH (галочка «Add to PATH» включена по умолчанию), на Linux — пакет |
| **Скрипт и образец конфига** — `setup-continue.ps1` (Windows) или `setup-continue.sh` (Linux) и `continue-config.example.yaml`, **в одной папке** | репозиторий проекта: `<ВСТАВИТЬ АДРЕС РЕПОЗИТОРИЯ>` |
| **Файл расширения** `continue-*.vsix` — если Marketplace закрыт | `<ВСТАВИТЬ ПУТЬ К VSIX>` |
| **Токен** к модели | Vault: `<ВСТАВИТЬ АДРЕС VAULT>`, путь `<ВСТАВИТЬ ПУТЬ>`, поле `<ВСТАВИТЬ ИМЯ ПОЛЯ>` |
| **Адреса** сервера модели и сервера поиска | `АДРЕС-OLLAMA` = `<ВСТАВИТЬ>`, `АДРЕС-СЕРВЕРА` = `<ВСТАВИТЬ>` |

Токен **не пересылать** в чатах и почте, **не коммитить**, не выкладывать
скриншотом. Скрипт спросит его сам со скрытым вводом — в команду его не
вписывать, иначе он останется в истории терминала.

---

## 2. Запустить скрипт

Скрипт делает всё, что можно сделать командами:

1. ставит расширение Continue;
2. выключает телеметрию Continue (в контуре ей некуда слать, но пытаться она
   будет);
3. пишет конфиг `~/.continue/config.yaml` с вашими адресами и токеном,
   прежний сохраняет рядом как `config.yaml.bak-<дата>`;
4. проверяет связь с моделью и со всеми MCP-серверами.

Закройте VS Code перед запуском.

### Windows (PowerShell)

```powershell
cd <ПАПКА СО СКРИПТОМ>
powershell -ExecutionPolicy Bypass -File .\setup-continue.ps1 -OllamaUrl http://АДРЕС-OLLAMA:11434 -ServerUrl http://АДРЕС-СЕРВЕРА -Vsix C:\путь\continue.vsix -Model qwen3.6:35b -ContextLength 32768
```

### Linux / macOS

```bash
cd <ПАПКА СО СКРИПТОМ>
bash setup-continue.sh --ollama http://АДРЕС-OLLAMA:11434 --server http://АДРЕС-СЕРВЕРА --vsix ~/путь/continue.vsix --model qwen3.6:35b --context 32768
```

Скрипт спросит токен — вставить из Vault (`Ctrl+V` / `Ctrl+Shift+V`, символы
не отображаются) и нажать Enter.

### Параметры

| Windows | Linux | Зачем |
|---|---|---|
| `-OllamaUrl` | `--ollama` | сервер с моделью, **обязательно** |
| `-ServerUrl` | `--server` | сервер поиска, без порта, **обязательно** |
| `-Vsix путь` | `--vsix путь` | поставить Continue из файла. Без него — из Marketplace |
| `-Model имя` | `--model имя` | модель чата |
| `-ContextLength N` | `--context N` | размер контекста модели. Не увеличивать без согласования: если больше, чем на сервере, ответы обрываются на середине |
| `-VaultPath путь` | `--vault-path путь` | взять токен из Vault самому (нужен `vault` CLI и выполненный `vault login`); поле — `-VaultField` / `--vault-field`, по умолчанию `token` |
| `-NoDojo` | `--no-dojo` | без DefectDojo — если уязвимости не нужны или порт 8012 вам не открыт |
| `-SkipExtension` | `--skip-extension` | Continue уже стоит, не трогать |

Повторный запуск безопасен: расширение не переставится, прежний конфиг
сохранится в копию. Так же обновляется конфиг, когда администратор меняет
образец (новые правила, адреса).

### Что скрипт выводит

```
== Токен
  [OK]   токен принят (40 символов)
== Расширение Continue
  [OK]   установлено
== Телеметрия Continue
  [OK]   выключена
== Конфиг Continue
  [OK]   записан: C:\Users\ivanov\.continue\config.yaml
== Связь с моделью
  [OK]   сервер отвечает, моделей: 3
== Связь с MCP-серверами
  [OK]   8010: kb_search, code_search, jira_search
  [OK]   8011: query_graph, get_node, get_neighbors, ...
  [OK]   8012: dojo_findings

Готово. Осталось вручную ...
```

| Сообщение | Что значит | Что делать |
|---|---|---|
| `VS Code не найден` | команды `code` нет в PATH | переустановить VS Code с «Add to PATH» или открыть новый терминал |
| `не установилось. Marketplace закрыт?` | нет доступа к Marketplace | добавить `-Vsix` / `--vsix` с путём к файлу |
| `доступ запрещён (401/403)` | неверный токен | скопировать заново из Vault, целиком |
| `в токене пробелы или не-латиница` | скопировалось лишнее | скопировать заново |
| `нет связи с ...` | адрес неверный или порт закрыт | проверить адрес; если верный — администратору |
| `шлюз не пропускает /api/tags (404)` | шлюз закрывает служебный адрес | не страшно, модель проверится в разделе 4 |
| `модели ... нет в списке сервера` | опечатка в `-Model` | запустить заново с правильным именем |
| `8010: не отвечает` | порт закрыт с вашей машины | администратору: какой порт |
| `8012: не отвечает` (жёлтым) | DefectDojo открыт не всем — так задумано | нужен — запросить доступ; не нужен — `-NoDojo` |
| `running scripts is disabled` (Windows) | политика запускать скрипты | запускать именно так, как в примере: `powershell -ExecutionPolicy Bypass -File ...` |

## 3. В VS Code: три действия

Их скрипт сделать не может — Continue хранит это у себя, а не в файлах.

### 3.1. Открыть VS Code и выбрать режим

1. Открыть VS Code (если был открыт — закрыть **все** окна и открыть снова:
   `Reload Window` не переподключает MCP-серверы).
2. Слева нажать значок **Continue**.
3. Вверху панели выбрать ассистента **Local Assistant**. Если Continue
   предлагает войти в аккаунт — закрыть, для нашего конфига вход не нужен.
4. Внизу окна чата переключить режим на **Agent**.

> Поиск работает **только в режиме Agent**. В режиме Chat модель
> инструментов не видит, и выглядит это как «поиск не работает».

### 3.2. Разрешить инструменты (Automatic)

По умолчанию Continue спрашивает разрешение перед каждым вызовом. Наши
инструменты **только читают** — ничего не меняют ни в Jira, ни в DefectDojo,
ни в базе, — поэтому им можно работать без подтверждения.

1. В строке ввода чата нажать значок **инструментов**.
2. Откроется список по серверам: `knowledge-base`, `code-graph`,
   `defectdojo`.
3. Нажимать на политику рядом с сервером, пока не станет **Automatic**.

| Что | Политика |
|---|---|
| `knowledge-base`, `code-graph`, `defectdojo` | **Automatic** |
| Встроенные инструменты Continue, которые **правят файлы или запускают команды в терминале** | оставить **Ask First** |

Надпись `-32601 Method not found` рядом с сервером **безобидна**: Continue
спрашивает у сервера то, чего у нас нет. Инструменты работают.

---

## 4. Проверить в чате

В режиме Agent задать три вопроса:

| Вопрос | Что должно произойти |
|---|---|
| `напиши функцию на Go, которая разворачивает строку` | ответ без инструментов — **модель работает** |
| `поищи в базе, как у нас согласуется выкладка в прод` | вызов `kb_search`, ответ со ссылкой на документ — **поиск по документации работает** |
| `посмотри в коде, где проверяется токен авторизации` | вызов `code_search`, ответ с путём `репозиторий/файл:строка` — **поиск по коду работает** |

Вызов инструмента виден в чате отдельным блоком, его можно развернуть:
там аргументы и ответ.

Всё прошло — готово.

## Как задавать вопросы

Модель сама решает, идти ли в поиск. Чтобы пошла — назовите, где искать.

| Хотите | Пример |
|---|---|
| Регламент, процесс | «**поищи в базе**, какие требования к паролям» |
| Именно Confluence | «что **в конфлюэнсе** про дежурства» |
| Место в коде | «**посмотри в коде**, где обрабатываются куки» |
| Параметры сборки | «**в коде**: какие параметры у джобы AA/asan» |
| Кто вызывает / что сломается | «кто вызывает шаг `abActions`» |
| Задачи | «**jira**: что открыто на Иванове в DEVSEC» |
| Уязвимости | «**dojo**: критичные в abinf» |

- **Jira — только со словом «jira»**, **DefectDojo — только со словом
  «dojo»**. Без слова эти инструменты не вызываются, так задумано.
- Задачи и уязвимости обновляются раз в два часа, код — раз в сутки ночью.
  Статус «прямо сейчас» сверяйте в самой Jira или DefectDojo.
- Нет ссылки на источник — ответ из общих знаний модели, а не из нашей базы.

## Если не работает

| Симптом | Что делать |
|---|---|
| Модель не зовёт инструменты | режим **Agent**, а не Chat (3.1) |
| Инструментов нет после смены конфига | закрыть VS Code полностью и открыть снова |
| 401 / 403 при ответе модели | перезапустить скрипт, вставить токен из Vault заново |
| Сервер MCP красный, `fetch failed` | перезапустить скрипт — он покажет, какой порт не отвечает |
| Ответ обрывается на середине | администратору: не совпадает размер контекста |
| `-32001 Request timed out` | модель загружается после простоя — повторить через полминуты |
| Каждый вызов спрашивает разрешение | раздел 3.2 |
| «Ничего не нашлось», хотя документ есть | переформулировать своими словами, назвать источник («в конфлюэнсе»); не помогло — администратору название документа |

Не проверяйте сервер поиска, открывая `http://АДРЕС-СЕРВЕРА:8010/mcp` в
браузере: адрес держит соединение и «висит» — это не ошибка.

## Приложение: то же самое без скрипта

Если скрипт запустить нельзя.

### Расширение

```bash
code --install-extension continue-x.y.z.vsix
```

Или в VS Code: `Ctrl+Shift+P` → **Extensions: Install from VSIX...**. Если
Marketplace открыт: `Ctrl+Shift+X` → **Continue** (издатель Continue) →
**Install**.

### Телеметрия

`Ctrl+,` → в поиске `continue telemetry` → снять галочку **Telemetry
Enabled**. Или добавить в `settings.json` строку
`"continue.telemetryEnabled": false`.

### Конфиг

Файл: Windows — `C:\Users\<логин>\.continue\config.yaml`, Linux / macOS —
`~/.continue/config.yaml`. Удалить всё, что там есть, вставить целиком и
заменить `АДРЕС-OLLAMA` (2 раза), `АДРЕС-СЕРВЕРА` (3 раза) и `ТОКЕН`
(2 раза, токен из Vault):

```yaml
name: Local Assistant
version: 1.0.0
schema: v1

models:
  - name: qwen3.6:35b
    provider: ollama
    model: qwen3.6:35b
    apiBase: http://АДРЕС-OLLAMA:11434
    roles: [chat, edit]
    capabilities:
      - tool_use
    keepAlive: -1
    defaultCompletionOptions:
      contextLength: 32768
      maxTokens: 2048
      temperature: 0.3
    requestOptions:
      headers:
        x-api-key: ТОКЕН

  - name: BGE-M3 Embed
    provider: ollama
    model: bge-m3:latest
    apiBase: http://АДРЕС-OLLAMA:11434
    roles: [embed]
    requestOptions:
      headers:
        x-api-key: ТОКЕН

mcpServers:
  - name: knowledge-base
    type: streamable-http
    url: http://АДРЕС-СЕРВЕРА:8010/mcp

  - name: code-graph
    type: streamable-http
    url: http://АДРЕС-СЕРВЕРА:8011/mcp

  - name: defectdojo
    type: streamable-http
    url: http://АДРЕС-СЕРВЕРА:8012/mcp

rules:
- Отвечай по-русски.
- Выбор инструмента. Про исходный код («где в коде», «в каком файле», «куда править») — code_search.
  Про регламенты, процессы и требования — kb_search. Про связи в коде (кто вызывает, что сломается)
  — инструменты code-graph. Про задачи — jira_search, и только если в сообщении есть слово «jira».
  Про уязвимости продуктов — dojo_findings, и только при слове «dojo» или «defectdojo».
- 'Названный источник — это уже просьба искать, глагол не нужен: «что у нас в конфлюэнсе про дежурство»
  — зови kb_search с source_filter="confluence".'
- 'Фильтры — отдельные аргументы, а не часть query. У jira_search это person, project, status, issue_key;
  у dojo_findings — product, status, severity. Фамилия или номер задачи, положенные в query, не найдут
  ничего: эти поля в тексте не хранятся. В query кладут только тему, и только если она есть в вопросе.'
- Если ты вызвал инструмент — отвечай по тому, что он вернул, и не придумывай имена файлов, пути,
  команды и ссылки, которых в ответе не было. Лишние фрагменты в выдаче — это нормально, молча игнорируй
  их. Если инструмент не вызывался, отвечай обычным образом, своими знаниями.
- 'Всегда показывай, откуда ответ: документ со ссылкой, файл со строкой, номер задачи, ссылку на находку.
  Если инструмент вернул поле citation — скопируй его дословно, вместе с путём.'
- Задачи и находки берутся из индекса, а не из живой системы. Если речь о статусе или количестве,
  добавь, на какую дату данные, и предложи свериться в источнике.
- 'Пустой ответ инструмента — так и скажи, не выдумывай. Но сперва подумай, тот ли инструмент ты позвал:
  поиск по документации не видит ни код, ни задачи, ни уязвимости.'
- У инструментов code-graph не заполняй параметр project_path — сервер уже настроен на нужный граф,
  а путь наугад даст ошибку «graph.json not found».
- 'Шаги Jenkins в графе называются по имени файла из vars/ (abActions), пайплайны — «репозиторий/путь»
  (billing/Jenkinsfile). Кто использует шаг или что он вызывает — get_neighbors с label = имя шага:
  стрелка <-- это вызывающие, --> вызываемые. query_graph для этого не подходит — он идёт только вперёд.'
- 'Просят документ, отчёт или сводку по уязвимостям продукта — зови dojo_findings
  с response_format="report" и пиши по возвращённым полям description, impact и
  mitigation, а не по своим знаниям: там написано, что нашёл конкретный сканер в
  конкретном месте. Ответ длинный, поэтому разумно сузить отбор по уровню.'
- 'Оформление: шаги — нумерованным списком, команды и пути — в блоках кода. Без эмодзи.'
```

Почему так:

- **Токен в `requestOptions.headers`, а не в `apiKey`.** `apiKey` уходит как
  `Authorization: Bearer ...`, а шлюз ждёт `x-api-key` и такой запрос
  отобьёт.
- **`rules`** — правила ответов: по-русски, со ссылкой на источник, без
  выдуманных путей и команд. Не удалять.
- **Блок `defectdojo`** можно удалить, если уязвимости не нужны.

### Проверка связи

Windows:

```powershell
Invoke-RestMethod -Uri "http://АДРЕС-OLLAMA:11434/api/tags" -Headers @{ "x-api-key" = (Read-Host "Токен") } | ForEach-Object { $_.models.name }
```

```powershell
$body = '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'; $h = @{ Accept = "application/json, text/event-stream" }; foreach ($p in 8010, 8011, 8012) { try { $r = Invoke-RestMethod -Uri "http://АДРЕС-СЕРВЕРА:$p/mcp" -Method Post -ContentType "application/json" -Headers $h -Body $body -TimeoutSec 20; "$p OK: " + (($r.result.tools | ForEach-Object name) -join ", ") } catch { "$p ОШИБКА: $($_.Exception.Message)" } }
```

Linux / macOS:

```bash
read -rsp "Токен: " T; echo; curl -s -H "x-api-key: $T" http://АДРЕС-OLLAMA:11434/api/tags
```

```bash
for p in 8010 8011 8012; do echo "== $p"; curl -s -X POST "http://АДРЕС-СЕРВЕРА:$p/mcp" -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | head -c 300; echo; done
```
