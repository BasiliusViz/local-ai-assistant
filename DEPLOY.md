# Развёртывание

Локальный ИИ-ассистент: поиск по внутренней документации и по коду, всё внутри
периметра. Наружу не уходит ни один запрос.

## Что нужно от сервера

- **Docker** с плагином compose v2
- **GPU NVIDIA** и `nvidia-container-toolkit`. Без GPU заработает, но
  генерация ответа займёт минуты вместо секунд
- **Диск:** 20 ГБ под модели, плюс место под базу (наши 850 документов заняли
  770 МБ; считайте ~1 ГБ на тысячу документов)
- **Видеопамять:** генеративная модель + эмбеддер должны помещаться
  ОДНОВРЕМЕННО (расчёт ниже)

Проверить GPU до начала:

```bash
docker run --rm --gpus all nvidia/cuda:12.4.0-base-ubuntu22.04 nvidia-smi
```

Если команда не отработала, ставьте `nvidia-container-toolkit` — без него
`docker compose` не увидит карту.

## Развёртывание

```bash
git clone <репозиторий> /srv/local-ai   # либо скопируйте папку
cd /srv/local-ai
cp .env.example .env
nano .env          # пути, модели, репозитории
./deploy.sh
```

`deploy.sh` делает всё: поднимает контейнеры, скачивает модели, создаёт
коллекции, индексирует документы и код, в конце запускает проверку. Он
останавливается на первой ошибке и объясняет, что делать.

Повторный запуск безопасен: модели не качаются заново, индексация обновляет
точки, а не дублирует.

## Проверка

```bash
./healthcheck.sh
```

Выводит список с отметками: контейнеры, сервисы, модели, наполненность
коллекций и **живой поиск** — то есть проверяет не «порт открыт», а что запрос
действительно что-то находит. Код возврата 0 при полном порядке, годится для
мониторинга.

## Подключение пользователей

В VS Code ставится расширение Continue, в `~/.continue/config.yaml`:

```yaml
models:
  - name: Ассистент
    provider: ollama
    model: qwen3:8b
    apiBase: http://СЕРВЕР:11434
    roles: [chat, edit]

mcpServers:
  - name: knowledge-base
    type: streamable-http
    url: http://СЕРВЕР:8010/mcp
  - name: code-graph
    type: streamable-http
    url: http://СЕРВЕР:8011/mcp
```

**Инструменты работают только в режиме Agent** — в обычном чате Continue их не
подключает. Переключатель внизу окна чата.

Файл правил из этого репозитория (`continue-rules.yaml`) стоит скопировать в
конфиг: без них модель отвечает сплошным текстом, не ссылается на источники и
иногда выдумывает. Проверено, каждое правило закрывает конкретную проблему.

## Обновление данных

**Код** (репозитории, граф, векторный индекс) — одной командой:

```bash
./update-code.sh
```

По расписанию, `crontab -e`:

```
0 * * * * cd /srv/local-ai && ./update-code.sh >> /var/log/local-ai-sync.log 2>&1
```

**Документы:**

```bash
docker compose exec kb python -m kb.doc_index /docs/internal --source local
```

Раскладывайте по подкаталогам и индексируйте с разными `--source`: потом можно
искать в конкретном источнике и отличать документацию от чужих текстов.

**Confluence** — отдельно, см. `confluence/README.md`. Скрипт выгружает
страницы в markdown, дальше их индексирует та же команда.

## Расчёт видеопамяти

Главное правило: **генеративная модель и эмбеддер должны помещаться в память
одновременно**. Поиск дёргает обе подряд, и если они не помещаются, каждый
запрос оплачивает перезагрузку модели с диска — это 17-77 секунд, и клиент
отваливается по таймауту. Симптом: «всё работало, потом стало тормозить».

Прикидка:

| Что | Сколько |
|---|---|
| Модель 8B, квантованная | ~5 ГБ |
| Модель 30-35B, квантованная | ~20 ГБ |
| KV-кэш при 8K контекста | ~0.5-2 ГБ (растёт с размером модели) |
| Эмбеддер bge-m3 | 0.7 ГБ |

На карте 12 ГБ помещаются 8B + эмбеддер с запасом. Для 35B нужно 24 ГБ и
больше.

Три параметра в `.env` управляют этим:

- `OLLAMA_CONTEXT_LENGTH` — **единый для всех моделей**. Ollama считает разные
  размеры контекста разными экземплярами: запрос на 32K плюс запрос на 8K
  создадут ДВА экземпляра одной модели, и они не поместятся. Для поиска по
  документам 8192 достаточно: пять фрагментов это 2-3 тысячи токенов
- `OLLAMA_MAX_LOADED_MODELS=2` — держать обе. Без этого Ollama оставляет одну
- `OLLAMA_KEEP_ALIVE=2h` — после простоя модели выгружаются. При 15 минутах
  первый запрос после перерыва ждал 77 секунд

Проверка, что обе модели в памяти:

```bash
docker exec ollama ollama ps
```

Должны быть обе строки и одинаковый CONTEXT. Если модель одна — смотрите
`MAX_LOADED_MODELS` и хватает ли видеопамяти.

## Если не работает

**`deploy.sh` останавливается на GPU.** Проверьте `nvidia-container-toolkit`
командой выше. Можно продолжить и без GPU, но будет очень медленно.

**Контейнер `Up`, но порт не отвечает** (`curl` даёт 000). Docker потерял
проброс портов, обычно после перезапуска WSL или демона. Лечится
`docker restart <имя>`, данные не задеваются.

**Поиск ничего не находит.** Проверьте наполненность коллекций в
`./healthcheck.sh`. Пустая коллекция = документы не проиндексированы.

**Поиск находит ерунду.** Скорее всего, эмбеддер не тот, которым индексировали.
Векторы разных моделей несовместимы, и поиск при этом НЕ падает с ошибкой, а
молча возвращает шум. Переиндексируйте, сменив `EMBED_MODEL`.

**Всё стало медленно.** `docker exec ollama ollama ps` — если моделей меньше
двух или у них разный контекст, они вытесняют друг друга. См. расчёт выше.

**Клиент отваливается по таймауту.** Первый запрос после долгого простоя грузит
модели с диска. Увеличьте `OLLAMA_KEEP_ALIVE` либо прогревайте по расписанию.

## Что не сделано

- **Аутентификации нет.** Порты 8010 и 8011 открыты всем, кто дотянется по
  сети. Внутри контура приемлемо, наружу выставлять нельзя
- **Права доступа не разграничены**: поле `acl_groups` заполняется значением
  `["all"]`. Оно проиндексировано, так что когда появятся реальные группы,
  фильтр заработает без переиндексации
- **Аудита запросов нет**
