# Развёртывание

Локальный ИИ-ассистент: поиск по внутренней документации и по коду, всё внутри
периметра. Наружу не уходит ни один запрос.

## Что нужно от сервера

- **Docker** с плагином compose v2
- **Диск** под базу: наши 850 документов заняли 770 МБ, считайте ~1 ГБ на
  тысячу документов
- **Доступ по сети к Ollama** — она разворачивается отдельно, на машине с
  видеокартой

**Видеокарта этому серверу не нужна.** В стеке три сервиса — Qdrant, `kb` и
`code-graph`, все считают на процессоре. Тяжёлая работа идёт на той машине, где
живёт модель.

Адрес модели задаётся в `.env`:

```
OLLAMA_URL=http://llm.company.local:11434/v1
OLLAMA_API_KEY=токен, если Ollama за шлюзом
```

На сервере с Ollama должны быть загружены обе модели — генеративная и
эмбеддер. Скрипт развёртывания
проверит их наличие по сети и не даст идти дальше, если чего-то нет.

Этот стек Ollama **не разворачивает и не настраивает** — только обращается к
ней по сети за эмбеддингами и генерацией. Никаких параметров ей не передаёт,
моделей не скачивает и не удаляет.

## Развёртывание

```bash
git clone <репозиторий> /srv/local-ai   # либо скопируйте папку
cd /srv/local-ai
cp .env.example .env
nano .env          # пути, модели, репозитории
./deploy.sh
```

`deploy.sh` делает всё: поднимает контейнеры, проверяет доступность модели,
создаёт коллекции, индексирует документы и код, в конце запускает проверку. Он
останавливается на первой ошибке и объясняет, что делать.

Повторный запуск безопасен: индексация обновляет точки, а не дублирует.

## Проверка

```bash
./healthcheck.sh
```

Выводит список с отметками: контейнеры, сервисы, модели, наполненность
коллекций и **живой поиск** — то есть проверяет не «порт открыт», а что запрос
действительно что-то находит. Код возврата 0 при полном порядке, годится для
мониторинга.

## Подключение пользователей

В VS Code ставится расширение Continue. Файл `continue-config.example.yaml` из
этого репозитория копируется целиком в `~/.continue/config.yaml`, в нём
заменяются три места: `АДРЕС-OLLAMA`, `АДРЕС-СЕРВЕРА` и `ТОКЕН`.

**Токен задаётся через `requestOptions.headers`, а не через `apiKey`.** `apiKey`
уходит как `Authorization: Bearer <токен>`, а шлюз, ждущий `x-api-key`, такой
запрос отобьёт. Continue обращается к модели напрямую, минуя `kb`, поэтому
настройки из `.env` на него не распространяются — заголовок нужен свой.

**Инструменты работают только в режиме Agent** — в обычном чате Continue их не
подключает. Переключатель внизу окна чата.

**После правки конфига — полный перезапуск VS Code.** Reload window не
переподключает MCP-серверы.

Правила ответов (`rules`) в примере уже внутри — это копия
`continue-rules.yaml`. Без них модель отвечает сплошным текстом, не ссылается на
источники и иногда выдумывает. Проверено, каждое правило закрывает конкретную
проблему.

Порты 8010 и 8011 должны быть открыты с машин пользователей. Аутентификации на
них нет — см. «Что не сделано».

## Обновление данных

**Код** (репозитории, граф, векторный индекс) — одной командой:

```bash
./update-code.sh
```

По расписанию, `crontab -e`:

```
0 * * * * cd /srv/local-ai && ./update-code.sh >> /var/log/local-ai-sync.log 2>&1
```

**Документы:**

```bash
docker compose exec kb python -m kb.doc_index /docs/internal --source local
```

Раскладывайте по подкаталогам и индексируйте с разными `--source`: потом можно
искать в конкретном источнике и отличать документацию от чужих текстов.

**Confluence** — отдельно, см. `confluence/README.md`. Скрипт выгружает
страницы в markdown, дальше их индексирует та же команда.

## Если поиск работает медленно

Настройки Ollama здесь не задаются — она чужая. Но одна её особенность
объясняет 90% жалоб на скорость, и об этом полезно знать, чтобы разговаривать
с теми, кто её держит.

**Генеративная модель и эмбеддер должны помещаться в видеопамять
одновременно.** Поиск дёргает обе подряд: сначала эмбеддер считает вектор
вопроса, потом генеративная модель формулирует ответ. Если в память помещается
только одна, Ollama выгружает и загружает их по кругу, и каждый запрос платит
за это 17–77 секунд. Симптом узнаваемый: «работало, потом стало тормозить».

На стороне сервера с моделью это лечится двумя переменными:
`OLLAMA_MAX_LOADED_MODELS=2` и достаточным объёмом видеопамяти. Ориентир: 8B в
квантованном виде занимает ~5 ГБ, 30–35B — ~20 ГБ, эмбеддер `bge-m3` — 0.7 ГБ,
плюс KV-кэш.

**Что можно сделать со своей стороны, не трогая чужой сервер:**

```
KB_EXPAND=0
```

Это выключает переформулировку запроса, и поиск обращается **только к
эмбеддеру** — генеративная модель в поиске не участвует вовсе, переключаться
Ollama не придётся. Качество на нашем наборе падает со 100% до 87%, зато
скорость возвращается.

Сначала разверните как есть и замерьте. Если поиск укладывается в пару
секунд — ничего менять не нужно.

## Если не работает

**`deploy.sh` не видит модель.** Проверьте `OLLAMA_URL` из браузера или
`curl`. Частая причина — Ollama слушает только localhost на своей машине,
ей нужен `OLLAMA_HOST=0.0.0.0`.

**Контейнер `Up`, но порт не отвечает** (`curl` даёт 000). Docker потерял
проброс портов, обычно после перезапуска WSL или демона. Лечится
`docker restart <имя>`, данные не задеваются.

**Поиск ничего не находит.** Проверьте наполненность коллекций в
`./healthcheck.sh`. Пустая коллекция = документы не проиндексированы.

**Поиск находит ерунду.** Скорее всего, эмбеддер не тот, которым индексировали.
Векторы разных моделей несовместимы, и поиск при этом НЕ падает с ошибкой, а
молча возвращает шум. Переиндексируйте, сменив `EMBED_MODEL`.

**Всё стало медленно** или клиент отваливается по таймауту. Скорее всего, на
сервере с моделью не помещаются обе сразу и они вытесняют друг друга — см.
раздел выше. Быстрый обход со своей стороны: `KB_EXPAND=0`.

## Что не сделано

- **Аутентификации нет.** Порты 8010 и 8011 открыты всем, кто дотянется по
  сети. Внутри контура приемлемо, наружу выставлять нельзя
- **Права доступа не разграничены**: поле `acl_groups` заполняется значением
  `["all"]`. Оно проиндексировано, так что когда появятся реальные группы,
  фильтр заработает без переиндексации
- **Аудита запросов нет**
