# Регламент выкатки сервиса payment-gateway

## Общие требования

Выкатка в прод возможна только после прохождения всех стадий пайплайна:
статический анализ, юнит-тесты, интеграционные тесты, сканирование образа.
Ответственный за релиз — дежурный DevOps инженер смены.

Окно выкатки: вторник и четверг, 10:00–16:00 MSK. Вне окна выкатка
допускается только по инциденту с приоритетом P1 и согласованием
руководителя направления.

## Подготовка релиза

Перед выкаткой нужно убедиться, что версия проставлена в файле VERSION,
changelog обновлён, а миграции базы данных совместимы с предыдущей версией.
Обратная совместимость обязательна: откат должен работать без потери данных.

Тег создаётся в формате v<major>.<minor>.<patch>, например v2.14.3.
Ветка релиза отводится от main и называется release/v2.14.3.

## Процедура выкатки

Выкатка идёт в три этапа. Сначала canary — один под из десяти, наблюдение
пятнадцать минут по метрикам error rate и p99 latency. При росте ошибок
выше 0.5% выкатка автоматически откатывается.

Затем 50% трафика, наблюдение тридцать минут. Затем полная выкатка.
Между этапами дежурный проверяет дашборд payment-gateway-release
в SigNoz и логи по фильтру service=payment-gateway level=error.

## Откат

Откат выполняется командой kubectl rollout undo deployment/payment-gateway.
Если проблема в миграции базы — сначала откатывается схема скриптом
migrate down, только потом деплой. Порядок обратный выкатке.

После отката обязательно создаётся постмортем в течение 48 часов.

## Контакты

Дежурная смена DevOps: канал #devops-duty.
Владелец сервиса: команда Payments, канал #team-payments.
Эскалация P1: звонок дежурному архитектору по расписанию on-call.
