# Выгрузка Confluence в базу знаний

Рассчитано на запуск в закрытом контуре без посторонней помощи. Скрипты
используют только стандартную библиотеку Python — ставить пакеты не нужно.

## Что происходит

```
Confluence API  ->  sync.py  ->  markdown-файлы  ->  kb/doc_index.py  ->  Qdrant
```

Два шага намеренно разделены: если разметка сконвертируется криво, это видно
в обычном `.md`-файле, а не в виде «поиск выдаёт ерунду».

## Порядок запуска

**0. Поставить зависимость**

```bash
pip install -r confluence/requirements.txt
```

Нужен только `requests`. Конвертер разметки обходится стандартной библиотекой.

**1. Настроить доступ**

Всё пишется в **`.env` в корне проекта** — там же, где настройки остального
стека. Отдельного файла для Confluence нет:

```
CONFLUENCE_URL=https://wiki.company.local
CONFLUENCE_TOKEN=ваш-PAT-токен
CONFLUENCE_SPACES=DEV,OPS
CONFLUENCE_OUT=/srv/local-ai/docs/confluence
```

Токен создаётся в Confluence: профиль → Personal Access Tokens. Это не пароль.
Уходит заголовком `Authorization: Bearer` — так его ждёт Server и Data Center.

`CONFLUENCE_OUT` должен быть внутри `DOCS_DIR`, иначе контейнер не увидит
выгруженные файлы при индексации.

**Что выгружать** — три настройки, их можно совмещать:

| Настройка | Что делает |
|---|---|
| `CONFLUENCE_SPACES=DEV,OPS` | пространства целиком, по **ключу** |
| `CONFLUENCE_SPACES=*` | все общие пространства (личные `~логин` не берутся) |
| `CONFLUENCE_PAGES=123456,789012` | страница и **всё поддерево под ней** |
| `CONFLUENCE_EXCLUDE=ARCH,123456` | что пропустить: ключ пространства или номер страницы — вместе с поддеревом |

**Какие пространства есть — показывает сам скрипт** (нужны только
`CONFLUENCE_URL` и `CONFLUENCE_TOKEN`):

```bash
docker compose exec kb python confluence/sync.py --list-spaces
```

Печатает ключи и названия всех пространств, которые видит токен, и готовую
строку `CONFLUENCE_SPACES=...` — лишнее из неё удалить. `--count` добавит
число страниц в каждом (дольше), `--personal` — личные пространства. Если
список пространств закрыт, скрипт сам попробует поиск, а если закрыт и он —
соберёт пространства по страницам.

**Ключ пространства — не название.** Он виден в адресе любой его страницы:
`.../display/DEV/...` или `.../spaces/DEV/...`. «Разработка» — название,
`DEV` — ключ. Номер страницы — там же: `...viewpage.action?pageId=123456`.

**Ключи или `*`?** Перечисленные ключи работают всегда: список всех
пространств при этом не запрашивается. `*` его запрашивает, а право на этот
список отдельное, и администраторы его часто закрывают — тогда будет 403 и
просьба перечислить ключи. Проверить, открыт ли список, — `--check` с `*`.

**Лишнее — в исключения.** В пространстве обычно есть черновики, архив, чужие
эксперименты, и всё это попадёт в поиск и будет цитироваться наравне с
действующими регламентами. Раздел «Архив» убирается одним номером его
страницы: исключается вместе со всем, что под ним. Уже выгруженное из
исключённого удаляется при следующем прогоне.

**2. Проверить связь — прежде чем что-либо качать**

```bash
python confluence/sync.py --check
```

На сервере то же самое внутри контейнера (там уже есть Python и настройки
из `.env`):

```bash
docker compose exec kb python confluence/sync.py --check
```

Покажет, установилось ли соединение, названия пространств и сколько страниц
в каждом будет выгружено (без исключённых). Если здесь ошибка, дальше идти
бессмысленно — см. раздел «Если не работает».

**3. Посмотреть, что будет сделано**

```bash
python confluence/sync.py --dry-run --limit 5
```

Ничего не записывает, только перечисляет файлы.

**4. Пробная выгрузка одного пространства**

Указать в `.env` одно пространство и запустить:

```bash
python confluence/sync.py --limit 20
```

**Открыть несколько файлов в `pages/` и проверить глазами**: сохранились ли
заголовки, таблицы, блоки кода. Это самый важный шаг — дальше по этим текстам
будет отвечать модель.

**5. Полная выгрузка и индексация**

```bash
python confluence/sync.py
docker compose exec kb python -m kb.doc_index /docs/confluence --source confluence
```

**6. Обновления — те же две команды**

В начале каждого файла — шапка с адресом страницы и её заголовком:

```
---
url: https://wiki.company.local/pages/viewpage.action?pageId=123456
title: Регламент выкатки
---
```

Индексатор кладёт адрес в ссылку поиска: ассистент цитирует страницу в
Confluence, а не путь к файлу на сервере. В текст для поиска шапка не
попадает. Ссылка по `pageId`, а не по заголовку — переживает переименование.

`sync.py` хранит версию каждой страницы в `.sync_state.json` и забирает только
изменившиеся. Переименованная или перенесённая в другое пространство страница
переезжает в новый файл, старый удаляется — иначе в поиске висели бы обе
версии. Индексатор пересчитывает только изменённые файлы: идентификатор
чанка детерминирован, повторный запуск обновляет точки, а не плодит дубли.

Разумно повесить обе команды на планировщик, раз в час или в сутки.

## Если не работает

Скрипт объясняет ошибки словами. Что делать в частых случаях:

**401, токен не принят.** Confluence Server/Data Center ждёт Personal Access
Token в заголовке `Bearer`. Если у вас Confluence **Cloud** — там другая схема
(email + API-токен через Basic auth), этот скрипт её не поддерживает, нужна
правка в `Client.get`.

**403 на /rest/api/space** при `CONFLUENCE_SPACES=*`. Список пространств
закрыт для токена. Перечислите ключи явно: `CONFLUENCE_SPACES=DEV,OPS` — список
тогда не нужен.

**«Пространства «X» нет или у токена нет к нему доступа».** Confluence отвечает
одинаково на оба случая. Чаще всего вместо ключа указано название, или ключ в
другом регистре — сверьте с адресом страницы.

**404 на всех запросах.** Скорее всего URL без подкаталога. Проверьте, как
выглядит адрес вики в браузере: если там `/confluence/`, он должен быть и в
`CONFLUENCE_URL`.

**Ответ не является JSON.** Обычно это HTML страницы логина: запрос ушёл
неаутентифицированным либо адрес ведёт не в API.

**Конвертация испортила разметку.** Сохраните сырой ответ и вынесите его
(обезличив) для разбора:

```bash
python confluence/sync.py --dump-raw raw.json --limit 1
```

В `raw.json` будет storage-формат страницы — по нему конвертер дорабатывается.

**Страница пропущена с ошибкой конвертации.** Выгрузка не падает целиком: имя
страницы печатается со сбоем, остальные обрабатываются дальше.

## Проверка без Confluence

Есть заглушка, повторяющая API Confluence Server со сложной разметкой
(таблицы, макросы, вложенные списки, ссылки на страницы):

```bash
python confluence/mock_server.py
```

```bash
CONFLUENCE_URL=http://localhost:8090 CONFLUENCE_TOKEN=test-token \
    python confluence/sync.py --check
```

На ней и отлаживался конвертер. Автотесты выгрузки поднимают заглушку сами —
пространства, исключения, пагинация, переименование и перенос страниц:

```bash
docker compose exec kb python confluence/test_sync.py
```

## Что осталось нереализованным

- **Права доступа.** Все страницы получают `acl_groups = ["all"]`. Поле
  проиндексировано в Qdrant с самого начала, так что когда появится выгрузка
  групп из Confluence, фильтр по правам заработает **без переиндексации**
- **Вложения** (картинки, pdf) не скачиваются: в текст попадает
  `[изображение: файл.png]`
- **Комментарии к страницам** не выгружаются
- **Confluence Cloud** — другая аутентификация и путь `/wiki/rest/api/`
