# Репозитории из Bitbucket и GitFlic по токену

`repos/sync.py` клонирует репозитории в `CODE_DIR` (например, `all_git`) и
обновляет уже склонированные. Оттуда их берут граф кода и поиск по коду.
Запускается на сервере, где лежит проект, — нужны `python3` (3.8+) и `git`
(2.31+). Сторонних пакетов не нужно.

## Настройка

В `.env` в корне проекта:

```ini
CODE_DIR=/srv/all_git
CODE_GIT_REPOS_FILE=repos/list.txt

BITBUCKET_URL=https://bitbucket.company.local
BITBUCKET_USER=svc-local-ai
BITBUCKET_TOKEN='токен как есть, со всеми спецсимволами'

GITFLIC_URL=https://gitflic.company.local
GITFLIC_USER=svc-local-ai
GITFLIC_TOKEN='...'
```

Список репозиториев — в `repos/list.txt`, по адресу на строку:

```bash
cp repos/list.example.txt repos/list.txt
nano repos/list.txt
```

```
https://bitbucket.company.local/scm/PROJ/billing.git
https://bitbucket.company.local/scm/PROJ/payments.git@develop   # комментарий
# https://bitbucket.company.local/scm/PROJ/legacy.git          <- выключен
```

- Адреса — те же, что дают кнопки «Клонировать → HTTPS», но **без логина и
  токена** в адресе. Скрипт сам подставит токен по хосту
- `@ветка` в конце необязательна, без неё берётся основная ветка
- `repos/list.txt` в git не попадает (у каждого сервера свой) — `git pull`
  его не тронет. Путь относительный от корня проекта, можно и абсолютный
- Вместо файла можно `CODE_GIT_REPOS=...` в `.env`, но только **в одну
  строку** через запятую. Можно и то и другое — списки сложатся
- Токен — **в одинарных кавычках**. Экранировать внутри ничего не нужно,
  кроме одного случая: если в самом токене есть одинарная кавычка, его проще
  перевыпустить
- `CODE_REPOS` оставить пустой: это старый способ, клонирование в контейнере

Клоны называются `сервис-проект-репозиторий`: `bitbucket-PROJ-billing`,
`gitflic-team-service-a`. Одного имени репозитория мало — `backend` бывает в
каждом проекте.

## Порядок запуска

```bash
python3 repos/test_sync.py          # сам скрипт работает на этой машине
python3 repos/sync.py --check       # доступ к каждому репозиторию, без скачивания
python3 repos/sync.py --dry-run     # что будет склонировано и что обновлено
python3 repos/sync.py               # клонировать и обновить
```

Код возврата — число ошибок, 0 значит всё хорошо.

Повторный запуск обновляет уже склонированное: `fetch` + `reset --hard` на
состояние сервера. Локальные правки в этих клонах **пропадут** — там их быть не
должно. Неотслеживаемые файлы (например, `graphify-out/` от графа кода)
остаются.

Отладка одного репозитория: `--only billing -v` — только те, где в имени есть
`billing`, и полный вывод git (токены в нём всё равно скрыты).

## Если что-то не так

Пришлите вывод `python3 repos/sync.py --check` и `python3 repos/test_sync.py` —
токенов в нём нет.

| Сообщение | Что делать |
|---|---|
| неверный логин или токен (401) | проверить `*_USER` и `*_TOKEN`; токен в одинарных кавычках |
| нет прав (403) | токен принят, но у пользователя нет доступа к репозиторию |
| репозиторий не найден (404) | адрес с опечаткой; Bitbucket так же отвечает и без прав |
| сертификат сервера не проверен | путь к корневому сертификату в `CODE_GIT_CAINFO` |
| хост не совпал ни с одним `<СЕРВИС>_URL` | адрес репозитория и `*_URL` различаются — токен не подставится |
| каталог есть, но это не git-репозиторий | в `CODE_DIR` уже лежит папка с таким именем — скрипт её не трогает |
| в каталоге другой репозиторий | то же, но там клон другого адреса |
| нужен git 2.31 или новее | обновить git на сервере |
| адрес без ключа — не прочитан | список в `.env` разнесён по строкам; перенести в `repos/list.txt` |
| файла со списком нет | проверить `CODE_GIT_REPOS_FILE`; относительный путь — от корня проекта |

## Как передаётся токен

Не в адресе: там спецсимволы токена ломают разбор, а сам адрес git сохраняет в
`.git/config` каждого клона. Скрипт передаёт git заголовок
`Authorization: Basic base64(логин:токен)` через переменные окружения
`GIT_CONFIG_*`: в `ps` их не видно другим пользователям, в клон ничего не
записывается, и заголовок привязан к адресу сервиса — на другой хост он не
уйдёт (это проверяет тест `test_header_not_sent_to_other_server`). Если
`*_USER` пуст, токен уходит как `Bearer`.
