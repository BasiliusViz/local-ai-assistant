# Проба OASIS: поиск уязвимостей в коде локальной моделью

Порядок команд для первого прогона на Windows. Цель пробы — **не внедрить
инструмент, а понять, стоит ли его внедрять**: сколько времени занимает прогон
и какая доля находок осмысленная. Если из десяти находок восемь мусор, дальше
идти незачем.

[OASIS](https://github.com/psyray/oasis) выбран вместо
[vulnhuntr](https://github.com/protectai/vulnhuntr) по трём причинам: не
привязан к одному языку (список расширений задаётся ключом), умеет SARIF на
выходе — значит находки уедут в DefectDojo без переходника, — и работает в две
ступени, что важно на одной видеокарте.

## Зачем прокси

OASIS принимает адрес Ollama, но **не умеет передавать ключ**, а наш шлюз без
`x-api-key` отвечает 403 — проверено. Поэтому между ними встаёт
`ollama_proxy.py`: слушает локально, подставляет ключ из `.env`, пересылает
как есть. OASIS о ключе не знает.

## Шаг 1. Прокси

Отдельное окно PowerShell, **оставить работать до конца пробы**:

```powershell
cd $HOME\Desktop\LOCAL-AI
.\.venv\Scripts\python.exe ollama_proxy.py
```

Печатает две строки, и обе надо прочитать:

- `Слушаю http://127.0.0.1:11435` — этот адрес даём OASIS. Локальный намеренно:
  внутри рабочий ключ, наружу его выставлять нельзя
- `Пересылаю в ...` — адрес вашей Ollama из `.env`. Если там `localhost` или
  `host.docker.internal`, значит адрес из мира контейнеров и снаружи не
  резолвится — задайте явно:

```powershell
.\.venv\Scripts\python.exe ollama_proxy.py --upstream http://АДРЕС-OLLAMA:11434
```

## Шаг 2. Проверка связи

Второе окно. Через прокси должен прийти список моделей:

```powershell
curl http://localhost:11435/api/tags
```

Пришёл 403 — ключ в `.env` не тот; в окне прокси видно сам запрос.

## Шаг 3. Установка

```powershell
git clone https://github.com/psyray/oasis.git $HOME\Desktop\oasis
```

```powershell
cd $HOME\Desktop\oasis
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
```

## Шаг 4. Модели видны?

```powershell
.\.venv\Scripts\oasis.exe --list-models -ol http://localhost:11435
```

Имена из этого списка подставляются в следующую команду.

## Шаг 5. Прогон

**По одному каталогу, не по всему репозиторию.** OASIS задуман на две модели —
лёгкая просеивает весь код, тяжёлая разбирает подозрительное. У нас пока одна
на обе роли, поэтому просеивание идёт тяжёлой и это медленно:

```powershell
.\.venv\Scripts\oasis.exe -i D:\путь\к\проекту\app -sm qwen3.6:35b -m qwen3.6:35b -em bge-m3 -ol http://localhost:11435 -v
```

Сузить типы файлов, если в каталоге лежит лишнее:

```powershell
.\.venv\Scripts\oasis.exe -i D:\путь --extensions py,js -sm qwen3.6:35b -m qwen3.6:35b -em bge-m3 -ol http://localhost:11435
```

## Что смотреть по итогу

**Время на каталог.** Умножьте на размер репозитория — станет понятно, реально
ли это по расписанию или нужна лёгкая модель на первую ступень (её придётся
просить выложить у тех, кто держит Ollama).

**Доля осмысленных находок.** Главный вопрос пробы. У LLM-анализа ложных
срабатываний много; если инструмент создаёт работу вместо экономии, он не нужен
ни в каком виде.

**Отчёты** складываются рядом с запуском в нескольких форматах: HTML посмотреть
глазами, SARIF — для импорта в DefectDojo, если решим продолжать.

## Если проба удалась

Дальше по плану, каждый шаг отдельно:

1. Контейнер рядом со стеком, код примонтирован только на чтение
2. SARIF уезжает в DefectDojo по API — **в отдельный продукт и не в статусе
   «открыта»**: смешивать находки LLM с находками Semgrep в одних метриках
   значит испортить метрики
3. Расписание раз в неделю по изменившимся репозиториям
4. Просить лёгкую модель для первой ступени

## Известные ограничения

- Лицензия GPL v3 — для внутреннего использования нормально, но показать
  юристам стоит
- Форк сторонний, код перед вводом в контур стоит прочитать: инструмент
  получает доступ ко всему исходному коду и ходит в модель
- Три модели по очереди на одной видеокарте упираются в перезагрузку — та же
  беда, что у ассистента. Пока обходим одной моделью
- Только чтение репозиториев. Никаких правок кода и никакой записи в DefectDojo
  сверх импорта находок
