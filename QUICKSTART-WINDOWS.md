# Развёртывание на Windows-сервере

Коротко и по шагам. Подробности, расчёты и разбор ошибок — в `DEPLOY.md`.

Модель (Ollama) здесь не разворачивается: она на отдельной машине с
видеокартой. На этом сервере работают Qdrant, поиск и граф кода — им хватает
процессора, **видеокарта не нужна**.

## Что нужно заранее

- **Docker Desktop** установлен и запущен
- **Сетевой доступ к Ollama** и её адрес. Проверить:
  ```powershell
  curl http://АДРЕС-СЕРВЕРА:11434/api/tags
  ```
  В ответе должны быть обе модели: генеративная и `bge-m3`. Если их нет —
  загрузить **на том сервере**: `ollama pull qwen3:8b`, `ollama pull bge-m3`
- **Диск с запасом**: база растёт примерно на 1 ГБ на тысячу документов

## 1. Забрать код

```powershell
git clone https://github.com/BasiliusViz/local-ai-assistant.git C:\local-ai
cd C:\local-ai
copy .env.windows.example .env
notepad .env
```

Заполнить `OLLAMA_URL`, при необходимости `OLLAMA_API_KEY`, проверить пути.

## 2. Разложить документы

В каталог из `DOCS_DIR` — **подпапками по источникам**:

```
D:\local-ai\docs\
    confluence\     выгрузка из вики
    internal\       локальные регламенты
```

Имя папки становится меткой источника: по ней потом можно фильтровать поиск и
отличать вики от прочего. Если свалить всё в корень — попадёт одной меткой.

### Выгрузка из Confluence

Настройки — в том же `.env`, что и весь остальной стек, отдельного файла нет:

```
CONFLUENCE_URL=https://wiki.company.local
CONFLUENCE_TOKEN=ваш-PAT-токен
CONFLUENCE_PAGES=123456
CONFLUENCE_OUT=D:\local-ai\docs\confluence
```

`CONFLUENCE_OUT` должен быть **внутри** `DOCS_DIR` — иначе контейнер не увидит
выгруженные файлы при индексации.

```powershell
pip install -r confluence\requirements.txt
```

`CONFLUENCE_PAGES` — идентификатор **корневой страницы**, виден в её адресе:
`.../pages/viewpage.action?pageId=123456`. Забирается сама страница и всё
поддерево под ней, на любой глубине. Токен создаётся в профиле Confluence,
раздел Personal Access Tokens — это не пароль.

```powershell
python confluence\sync.py --check     # связь, спейсы, сколько страниц
python confluence\sync.py --dry-run   # что будет выгружено, без записи
python confluence\sync.py             # выгрузка
```

**Откройте пару выгруженных файлов и посмотрите глазами**: сохранились ли
заголовки, таблицы, блоки кода. По этим текстам будет отвечать модель, и проще
поймать проблему здесь, чем потом гадать, почему поиск врёт.

Повторный запуск забирает только изменившиеся страницы — состояние хранится
рядом с выгрузкой, в `.sync_state.json`.

Подробности и разбор ошибок — `confluence/README.md`.

## 3. Код (если нужен поиск по нему)

Два варианта:

- код уже на сервере — положить так, чтобы получилось
  `CODE_DIR\repos\<репозиторий>`, а `CODE_REPOS` оставить пустым
- клонировать заново — вписать в `CODE_REPOS` адреса через запятую, с токеном
  в URL

## 4. Развернуть

```powershell
.\deploy.ps1
```

Шесть шагов с проверкой на каждом. Останавливается на первой ошибке и
объясняет, что делать. Повторный запуск безопасен.

## 5. Проверить

```powershell
.\healthcheck.ps1
```

Все строки должны быть зелёными. Проверяется не «порт открыт», а что поиск
действительно что-то находит.

## 6. Подключить пользователей

В `~/.continue/config.yaml` на машине каждого:

```yaml
models:
  - name: Ассистент
    provider: ollama
    model: qwen3:8b
    apiBase: http://АДРЕС-OLLAMA:11434
    apiKey: ТОКЕН        # если Ollama за шлюзом
    roles: [chat, edit]

mcpServers:
  - name: knowledge-base
    type: streamable-http
    url: http://АДРЕС-СЕРВЕРА:8010/mcp
  - name: code-graph
    type: streamable-http
    url: http://АДРЕС-СЕРВЕРА:8011/mcp
```

Плюс скопировать туда содержимое `continue-rules.yaml` — без правил модель
отвечает сплошным текстом, не ссылается на источники и иногда выдумывает.

**Инструменты работают только в режиме Agent** (переключатель внизу окна чата).
После правки конфига — **полный перезапуск VS Code**, перезагрузки окна мало.

## 7. Обновления по расписанию

Код (репозитории, граф, индекс):

```powershell
schtasks /create /tn "local-ai code" /tr "powershell -File C:\local-ai\update-code.ps1" /sc hourly
```

Документы — после каждого пополнения. Для Confluence это две команды подряд,
их удобно положить в один `.bat` или задание планировщика:

```powershell
python confluence\sync.py
docker compose exec kb python -m kb.doc_index /docs/confluence --source confluence
```

Индексация обновляет только изменившиеся файлы: идентификатор чанка выводится
из пути и номера, повторный запуск переписывает точки, а не плодит дубли.

## Если что-то не так

**`deploy.ps1` пишет, что Ollama недоступна.** Проверьте адрес из браузера или
`curl`. Частая причина — Ollama слушает только localhost на своей машине: ей
нужен `OLLAMA_HOST=0.0.0.0`.

**Модель не найдена на сервере.** Загрузить её там: `ollama pull <модель>`.
Отсюда это сделать нельзя.

**Контейнер работает, но порт не отвечает.** Docker потерял проброс портов
(бывает после перезапуска WSL). Лечится `docker restart <имя>`, данные не
задеваются.

**Поиск ничего не находит.** Посмотрите в `healthcheck.ps1` наполненность
коллекций: пустая коллекция означает, что документы не проиндексированы.

**Поиск находит ерунду.** Скорее всего, `EMBED_MODEL` не тот, которым
индексировали. Векторы разных моделей несовместимы, и поиск при этом не падает
с ошибкой, а молча возвращает шум. Исправить модель и переиндексировать.
