## Следующий шаг: попробовать MCP для Jira и Confluence

Пользователь хочет протестировать готовый MCP-сервер для Jira и Confluence
рядом с нашим индексом.

- **Официальный Atlassian Rovo MCP Server не подходит**: только Atlassian
  Cloud, с Server/Data Center не соединяется, сам живёт в облаке. У
  пользователя Server/DC в закрытом контуре
- **Кандидат — `sooperset/mcp-atlassian`** (неофициальный, самый
  распространённый): Server/DC 8.14+ по персональному токену, разворачивается
  у себя, транспорты SSE и streamable-http
- Замысел: **не замена, а дополнение**. Наш индекс — смысловой поиск по
  истории («как решали X»); mcp-atlassian — живые точные запросы («статус
  DEVSEC-412», «что на мне»), JQL/CQL
- Обязательные настройки (имена из его документации, НЕ проверены на деле):
  `READ_ONLY_MODE=true` (иначе модель создаёт и меняет задачи от имени токена),
  `ENABLED_TOOLS` или `TOOLSETS=default` (всего 98 инструментов — забьют
  контекст, будет «message exceeds context limit»), `JIRA_PROJECTS_FILTER`,
  `CONFLUENCE_SPACES_FILTER` (на порту нет авторизации — граница доступа),
  `JIRA_URL` + `JIRA_PERSONAL_TOKEN`, `CONFLUENCE_URL` +
  `CONFLUENCE_PERSONAL_TOKEN`, `TRANSPORT`, `PORT`
- План: блок в `docker-compose.yml` (свой порт, например :8013), переменные в
  `.env.example`, список из 5–8 инструментов только на чтение, правило в
  Continue — когда звать его, а когда `jira_search`/`kb_search`. Образ или
  пакет попадает в контур через зеркало — проверить, отдаёт ли оно его
