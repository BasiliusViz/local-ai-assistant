# План: веб-чат в браузере на Open WebUI

То же, что Continue в VS Code (модель + наши MCP), но в браузере и для тех, у
кого нет VS Code.

**Пока один пользователь — сам владелец (решение 08.10.2026).** Группы, две
модели и доступ к Dojo по группам отложены: один админ, одна модель со всеми
инструментами, регистрация закрыта (`ENABLE_SIGNUP=false` после первого входа).
Камни 9 и 13 вернутся, когда появятся другие пользователи. Open WebUI — один контейнер рядом со стеком. Он только
читает наши MCP и разговаривает с Ollama, свой поиск по базе не нужен.

## Почему Open WebUI, а не другое (08.10.2026)

- **Open WebUI**: офлайн-режим описан в документации; модели для его
  встроенного RAG вшиты в образ; телеметрия выключена по умолчанию; MCP
  (streamable-http) поддерживается штатно; есть пользователи, группы, доступ
  по группам
- **opencode**: агент в терминале для программиста, а не чат для команды.
  При старте качает каталог моделей, плагины, обновления; офлайн-режима
  нет, есть жалобы на зависание без сети
- **LibreChat**: те же вопросы офлайна плюс MongoDB и Meilisearch
- **Свой мини-чат**: запасной вариант, если Open WebUI не встанет

## Что проверено

- Шлюз Ollama пропускает всё, что нужно Open WebUI (`check-ollama-gateway.sh`)
- Egress сервера чист (`check-egress.sh --watch 600`; разовое обращение
  контейнера к GitHub было во время сборки)

## Подводные камни закрытого контура и решения

| # | Камень | Решение |
|---|---|---|
| 1 | Модели (эмбеддинги MiniLM, bge-micro, Whisper, tiktoken) вшиты в `/app/backend/data/cache`. Пустая папка хоста (bind mount) их **закроет**, и Open WebUI пойдёт качать | **Именованный том** Docker: при первом запуске в него копируется содержимое образа |
| 2 | `OFFLINE_MODE` выключает только то, что Open WebUI делает сам (версии, HuggingFace). То, что настроишь сам (веб-поиск, внешние API), не блокирует | Не включать внешнее; после запуска проверить `check-egress.sh --watch` |
| 3 | `fetch_url` / `search_web` — встроенные инструменты: модель сама ходит по URL с сервера | `ENABLE_WEB_SEARCH=false` глобально: без него их нет |
| 4 | Ollama по умолчанию даёт окно 4096 токенов: ответы инструментов обрежутся, ответ «из двух символов» | `DEFAULT_MODEL_PARAMS={"num_ctx": 32768}` |
| 5 | Настройки из env применяются только при первом старте, дальше живут в базе | Так и оставить (иначе MCP и группы, заданные в админке, сбросятся при перезапуске). Менять потом — в админке |
| 6 | В админке есть скачивание и удаление моделей Ollama (`/api/pull`, `/api/delete`) | Админ — только ты; у владельца шлюза спросить, закрыты ли эти пути. Если нет и закрыть нельзя — фильтр путей (расширить `ollama_proxy.py`) |
| 7 | Фоновые вызовы модели: заголовки, теги, подсказки, автодополнение на каждый символ | Выключить переменными (`ENABLE_*_GENERATION=false`), заголовки чатов оставить |
| 8 | Встроенные инструменты native-режима (память, поиск по чатам, заметки) лишние и едят окно | В нашей модели в Workspace снять «Builtin Tools» |
| 9 | Админ по умолчанию видит все чаты, а в них находки Dojo и код | `ENABLE_ADMIN_CHAT_ACCESS=false` |
| 10 | Пароли идут по HTTP открытым текстом внутри сети | Пока как у остальных портов. Позже — TLS через обратный прокси |
| 11 | Тег `:main` меняется каждый день, а в контур образ заносится руками | Закрепить версию: `v0.11.4` (полный образ, не `slim`: в slim с 0.11.4 нет вшитых моделей) |
| 12 | Образ весит несколько ГБ, ghcr.io из контура может быть недоступен | Через Nexus (`WEBUI_IMAGE`), иначе `docker save` / `docker load` |
| 13 | Доступ к Dojo только для AppSec (сейчас граница — порт) | Две модели в Workspace: «LOCAL-AI» без Dojo — всем, «LOCAL-AI AppSec» с Dojo — только группе AppSec; сам MCP Dojo с доступом только этой группе |
| 14 | В Continue инструменты зовутся только с подтверждения («Ask first»), здесь подтверждения нет — модель решает сама | Все инструменты только на чтение, правило «звать по слову» — в системном промпте. Принимаем |
| 15 | Голосовой ввод тянет Whisper (вшит), но лишний | В админке выключить STT/TTS |

## Шаги

| # | Что | Где |
|---|---|---|
| 0 | Образ `v0.11.4` на сервер: через Nexus или `docker save`/`load` с машины с интернетом | команды по одной |
| 1 | Сервис `open-webui` под профилем `webui`: именованный том, порт 3000, офлайн-переменные, ключ шлюза своим заголовком (`OLLAMA_API_CONFIGS`), `num_ctx`, всё лишнее выключено (камни 1–4, 7, 9, 11) | `docker-compose.yml` |
| 2 | Переменные с пояснениями: `WEBUI_IMAGE`, `WEBUI_PORT`, `WEBUI_SECRET_KEY`, `WEBUI_OLLAMA_URL` (адрес без `/v1`) | `.env.example` |
| 3 | Запуск, первый вход — ты админ; затем `check-egress.sh --quiet --watch 600` до любых настроек | сервер |
| 4 | В админке: MCP `kb`, `code-graph`, `cb-graph`, `dojo`; выключить STT/TTS; закрыть регистрацию | инструкция |
| 5 | Workspace → модель «LOCAL-AI» поверх qwen: системный промпт из `continue-rules.yaml`, все четыре MCP, без Builtin Tools (камень 8) | инструкция |
| 6 | Проверка: обычный вопрос; «поищи в базе ...» -> `kb_search`; «что в dojo по ...» -> `dojo_findings`; снова `check-egress.sh --watch` | сервер |
| 7 | Инструкция для админа и пользователей; строка в `CLAUDE.md` и `USER-GUIDE` | `guides/OPEN-WEBUI.md` |

Шаги 1–2 и 7 — код и документы (одна сессия). Шаги 0, 3–6 — на сервере по
одной команде. Шаги 4–5 делаются в админке руками: в env MCP задаются только
в формате, который «может меняться», а доступ по группам всё равно в админке.
