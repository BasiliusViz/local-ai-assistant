# План: описания репозиториев релиза CB18.5, которые пишет модель

Продолжение `guides/PLAN-CB-GRAPH.md` (сессия 2 — карточки, `cb_repos`, Obsidian — сделана и
развёрнута 01.10.2026). Записано 01.10.2026, делать в новой сессии.

## Зачем

README в репозиториях релиза почти пустые («ничего путного нет» — пользователь), карточки
из них бедные. Пользователь не знает продукт и хочет, чтобы модель прочитала код и сама
написала README, а потом по нему отвечала (`cb_repos`, Obsidian).

## Решение: пересказ снизу вверх по папкам

Весь код в контекст не влезет (`main` — 2 млн узлов графа). Модель каждый раз видит одну папку:

```
скелет файлов (без модели) -> пересказ папки (модель) -> ... -> README репозитория (модель)
```

1. **Файл — без модели:** функции/классы/методы с сигнатурами и строкой — из `graph.sqlite`
   (узлы с `source_file`, `loc`), плюс первые строки комментария файла. Как «карта
   репозитория» у aider: сигнатуры, отобранные по связям, а не код.
2. **Папка — один вызов:** скелеты её файлов + пересказы подпапок -> 3–5 фраз. Мелкие папки
   (порог — узлов графа, ~20) сливаются в родительскую. Пересказ хранится с хешем входа:
   повторный прогон считает только изменившееся.
3. **Репозиторий — один вызов:** пересказы верхних папок + манифесты, зависимости, точки входа
   (`main.go`, `*Application.java`, Dockerfile), конфиги (порты, адреса, топики) -> README:
   назначение, части, вход/выход, зависимости.
4. **В карточку:** поле «описание (сгенерировано моделью)» рядом с настоящим README, с
   пометкой. В `cb_repos`, Obsidian (по желанию — заметка на модуль), `services.yaml` (purpose).

Вызовы модели — через `/v1`, `reasoning_effort: "none"`, только stdlib.

## Открытый вопрос — где генерировать

Шлюз пускает сервер только к `/api/embed`. Continue ходит в модель напрямую с машины
пользователя.
- **А.** Попросить открыть серверу генерацию (`/v1` или `/api/chat`) — всё на сервере одной
  командой.
- **Б.** Без изменений доступа: сервер собирает выжимки в архив -> пользователь забирает к
  себе -> скрипт на его машине гоняет через модель -> результат одним JSON обратно на сервер
  -> `repo_cards.py` подмешивает.

Ответа пользователя ещё нет.
